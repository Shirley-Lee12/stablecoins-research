# 1. 网站要回答的核心问题

普通用户第一次进入专题，不应该先看到一串缩写。

1. **AI 现在真的可以替我付款了吗？**
2. **AI 能花多少钱？谁控制？**

6. **如果 AI 买错、被骗或被攻击，谁负责？**

所有后续页面都围绕这 6 个问题展开。

# 4. 首页第二张图：AI 到底有多少花钱权限？

标题：

> **How much control does the agent have?**

建议做成 3 档横向滑块。

## Level 1 — 每次都问我

**Human-confirmed**

```text
Agent finds item
→ shows final amount
→ User approves
→ Payment
```

典型：

- Muse + Stripe Link
- Grok Bot + Link / X Money
- ChatGPT Instant Checkout

适合：

- 高价值消费
- 新 Agent
- 普通消费者购物

---

## Level 2 — 满足条件就可以买

**Pre-authorized / delegated**

```text
User sets:
≤ ¥500
ticket only
before Friday
one purchase
→ Agent acts within limits
```

典型：

- AP2 mandate
- AMP task authorization
- APOP structured intent
- Antom conditional purchase

适合：

- 抢票
- 限价购买
- 低风险固定任务

---

## Level 3 — 机器自主支付

**Autonomous / machine-native**

```text
Agent needs resource
→ receives payment request
→ pays automatically
→ gets result
```

典型：

- x402
- MPP
- 支付宝 Machine Pay
- AMP A2A nano-payment

适合：

- API
- 数据
- 推理
- 算力
- 高频微支付

# 5. 首页第三张图：三种资金控制模型

这一图用于解释“AI 有没有拿到我的钱”。

## Model A — Mandate Model

代表：

- AP2
- APOP
- ACT / AMP 的部分设计

```text
User
 ↓
Structured mandate
金额 / 时间 / 商户 / 次数 / 商品
 ↓
Agent
 ↓
Payment provider verifies mandate
 ↓
Payment
```

一句话：

> **AI 拿到的是任务权限，不是整个账户。**

---

## Model B — Scoped / Virtual Credential

代表：

- Muse + Stripe Link
- ACP Delegate Payment

```text
User approval
 ↓
Wallet / PSP
 ↓
Scoped token / one-time card
 ↓
Agent
 ↓
Merchant
```

一句话：

> **AI 可以用一个受限凭证付款，但不必看到真实银行卡。**

---

## Model C — Platform Account + Approval

代表：

- Grok Bot + X Money
- 部分平台型支付体系

```text
User account / balance
 ↓
Agent proposes payment
 ↓
User Allow / Deny
 ↓
Platform payment account
 ↓
Merchant
```

一句话：

> **Agent 使用平台账户，但付款前仍受平台审批和账户规则控制。**

# 6. 首页第四张图：三条支付轨道

标题：

> **The agent can pay with different kinds of money.**

三列：

## Card / Bank Network

代表：

- Visa
- Mastercard
- UnionPay
- ACH
- UPI

优势：

- 商户覆盖广
- 退款与争议成熟
- 消费者保护强

局限：

- 微支付经济性较弱
- machine-to-machine 原生性较弱
- 全球跨境规则复杂

---

## Wallet / APM

代表：

- Alipay
- Alipay+
- GCash
- DANA
- TNG eWallet
- Shop Pay

优势：

- mobile-first
- 亚洲 / 新兴市场覆盖强
- 用户已有余额和身份体系

局限：

- 跨钱包互操作仍在发展
- 平台依赖较强

---

## Stablecoin / Blockchain

代表：

- x402 原生路径
- MPP stablecoin rail
- 未来 Agent-to-Agent programmable payment

优势：

- 24/7
- machine-friendly
- 微支付
- 可编程
- 跨境
- API-native

局限：

- 钱包和私钥风险
- 稳定币发行人风险
- 不可逆性
- 监管与合规
- 商户接受度仍在发展

底部结论：

> **Stablecoin is one rail, not the whole agentic-payment stack.**

# 14. Risk Map

建议路径：

`/agentic-payments/risks`

做成一张从 User → Agent → Authorization → Payment → Settlement 的风险链。

---

## 14.1 User Intent Risk

例：

> 用户说“便宜一点”，Agent 到底理解成多少？

风险：

- 模糊指令
- 隐含条件遗漏
- 用户不知道授权范围

缓解：

- structured intent
- confirmation
- clear limits

---

## 14.2 Agent Risk

风险：

- hallucination
- prompt injection
- malicious webpage
- tool compromise
- model manipulation
- Agent identity spoofing

缓解：

- KYA
- trust rating
- secure execution
- deterministic authorization surface

---

## 14.3 Authorization Risk

风险：

- over-delegation
- replay
- scope escalation
- stale permission
- duplicate execution

缓解：

- amount limit
- merchant binding
- time limit
- frequency limit
- nonce / idempotency
- revocation
- mandate receipts

---

## 14.4 Credential Risk

风险：

- raw card exposure
- API secret leakage
- wallet key theft
- session compromise

缓解：

- scoped token
- one-time card
- secure vault
- MPC
- device binding
- short expiry

---

## 14.5 Merchant / Service Risk

风险：

- fake merchant
- malicious API
- service not delivered
- deceptive pricing
- delivery failure

缓解：

- merchant identity
- reputation
- escrow
- refund
- purchase protection

---

## 14.6 Payment Risk

风险：

- duplicate charge
- fraud
- chargeback
- wrong amount
- unauthorized transfer

缓解：

- idempotency
- real-time monitoring
- velocity limits
- risk scoring

---

## 14.7 Stablecoin-specific Risk

风险：

- depeg
- issuer failure
- redemption stress
- private key loss
- smart contract
- chain congestion
- bridge
- sanctions
- irreversible settlement

---

## 14.8 Accountability Risk

最终必须回答：

- 用户授权了什么？
- Agent 做了什么？
- 商户展示了什么？
- PSP 批准了什么？
- 钱什么时候转移？
- 谁保存证据？
- 谁承担损失？

这也是 AP2 Mandate / Receipt、ACT 可追溯、APOP 意图管理、AMP KYA 等设计共同关注的问题。

# 25. 最终网站的核心观点

专题最终不应该变成：

> “列举谁发布了 AI 支付产品。”

真正应该让用户理解：

> **Agentic Payment 是一套新的委托经济基础设施。**

它要求金融系统同时回答：

1. **谁是 Agent？**
2. **它代表谁？**
3. **它被允许做什么？**
4. **它能花多少钱？**
5. **它用什么凭证？**
6. **钱走哪条 rail？**
7. **交易如何结算？**
8. **发生错误时谁能证明发生了什么？**
9. **谁承担损失？**

而 Stablecoin Research Hub 最有价值的切入点是：

> **稳定币不是 Agentic Payment 的全部，也不是必要条件；但在 machine-to-machine、微支付、24/7、跨境和可编程结算这些场景中，它可能成为极具竞争力的底层 rail。**

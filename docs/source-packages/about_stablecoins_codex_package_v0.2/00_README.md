## Positioning

This is a concise but rigorous introductory layer.
It should help a new user understand mechanisms before entering Research, Regional Developments, Market Data or Agentic Payments.

It is **not** a primary sidebar-heavy research pillar.

## Core explanatory model

For any stablecoin, ask:

1. What reference value is it trying to track?
2. What economically supports the claim and absorbs losses?
3. How are tokens issued, circulated and exited/redeemed — and by whom?
4. After a deviation, what mechanism is supposed to restore the reference value?

Stablecoin labels are secondary to these mechanisms.

## Editorial boundaries

- Application ≠ adoption.
- Attestation ≠ audit.
- Issuer redemption rights ≠ every secondary-market holder having direct issuer redemption access.
- Stablecoin ≠ CBDC.
- Stablecoin ≠ tokenised bank deposit.
- Stablecoin ≠ tokenised money-market fund share.
- “Algorithmic” is a mechanism label, not a synonym for every decentralised stablecoin.
- Current project classification must follow the current mechanism, not a historical brand label.
- Do not use a fixed taxonomy as if categories are legally universal or mutually exclusive.

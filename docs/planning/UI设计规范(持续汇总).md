## 1. Resources 列表页

**视觉方向**:不用卡片,改成传统学术数据库风格(参考 Web of Science / 知网)。

**✅ 字段已确认**:标题、作者、年份、来源机构、引用量(见第2、2b条)。标签不在列表页展示胶囊,只在详情页完整展示。

- 支持排序:按年份、按引用量
- 标题点击 → 跳站内详情页(不变,沿用15号原有规则)

## 2. 引用量字段(新增,已做可行性分析)

**结论**:对有DOI/能被数据源收录的资源可行,成本低;对政府监管文件、部分工作论文等无法收录的资源基本查不到,必须设计成允许缺失的可选字段。

- 现有上传管线(U.1/U.2)已用 OpenAlex、Semantic Scholar、Crossref 做反查链接,三者返回结果本身就带引用数(`cited_by_count`/`citationCount`/`is-referenced-by-count`),目前只是没持久化——复用已有调用即可,不需要新增API成本
- 查不到的资源:显示"暂无数据",不能显示成0(0和"没查到"含义不同)
- 引用数是抓取时刻的快照会过期,展示需标注"截至XXXX年XX月"
- **不纳入六要素完整性判断,不作为必填字段**,缺了不影响 approved/incomplete 状态判定
- 定期刷新(如每月重跑)可后续迭代,现在先做"上传时抓一次快照"

## 2b. 来源机构字段(新增,语义已确认)

**填写优先级(统一规则,不按文献类型分流判断)**:
1. 优先填**最终发表的期刊**(适用于大部分正式发表的journal论文)
2. 没有正式发表(比如还停留在working paper阶段)→ 填**发布平台**(如NBER、SSRN)
3. 机构发布的文件(法案、新闻稿等):**作者和来源机构可以填一样的值**(比如都是"Hong Kong Monetary Authority"),不用担心信息重复,两个字段各自如实填写即可,不需要为了避免重复而把机构名从"作者"挪走或留空

这个优先级是统一适用的规则,**不是"学术论文走A逻辑、监管文件走B逻辑"这种按类型分流**——不管什么类型的文献,都按"先看有没有正式发表期刊,没有就看发布平台"这一条规则去找。

**可行性,跟引用量类似**:
- 有DOI的资源:Crossref 的 `container-title` 等字段本身就区分"期刊名"还是"working paper系列名",大概率能直接对上这个优先级,复用已有反查调用即可
- PDF抽取的资源:LLM抽取prompt里按这个优先级顺序找——先找有没有明确写着发表期刊,没有则找发布平台/机构落款,遵循项目一贯的"原文没有明确写就留空,不许编造"原则
- 手填/无法识别的资源:留给用户手动填写,可选不强制

## 3. 后台审核队列(多维表格)

**视觉方向**:数据后台风格(参考 Notion / Linear),不是卡片列表。

功能需求(20号文档已定,这里补充视觉方向):分类筛选(新资源提交 vs 编辑建议)、按时间排序、按状态筛选(待审核/已拒绝/已通过)、检索(标题/提交人)。
